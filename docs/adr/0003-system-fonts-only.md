# System font stack for body/UI text; one self-hosted display face

Body and UI text use a system font stack (`-apple-system, "Segoe UI", Roboto, sans-serif`, already used in the ticket-13 CSS) — never a third-party-hosted web font (e.g. a Google Fonts CDN `<link>`). The site targets 3G/4G mountain connections and ticket 13 already stripped every unnecessary asset (WP core emoji scripts, Contact Form 7 loading sitewide) to keep page weight down; a third-party font CDN would reintroduce exactly the kind of extra DNS/connection round-trip that pass eliminated.

Headings use one self-hosted display face (Lora, semibold) — a single Latin-subset WOFF2 file served from the theme itself (no external request), loaded with `font-display: swap` so text is never invisible while it loads. This is a deliberate amendment to the original "no web fonts at all" version of this decision: a generic system sans as the *display* voice reads as no design decision at all, and the actual performance cost here is one small (<20KB), theme-hosted, browser-cached file — not the third-party-request problem this ADR exists to prevent. Reversing either half later means auditing every template for hardcoded font-family assumptions, not flipping a setting.
